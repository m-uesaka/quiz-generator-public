# 題材・切り口ガイド

> **このファイルは「叩き台」です。** 実際にはあなたの過去問や、Obsidian に溜まっている
> クリップの傾向そのものがあなたの趣味を表しています。50〜100 問ぶんの作問ログが
> 溜まったら、Claude に分析させてこのファイルを作り直してください（`README.md` 参照）。

## 1. 基本方針

題材そのもののジャンルに偏らず、「知識の引っかかり」を重視する。

- 一般知識と少し専門的な情報の境目にある題材を選ぶ。
- 有名なものを、やや意外な周辺情報から問う。
- 固有名詞を直接問う場合でも、代表作の羅列ではなく、時期・役割・別分野の実績・語源・制度・事件などを組み合わせる。
- 「聞いたことはあるが、答えまで一直線には出ない」程度の負荷を好む。
- 硬い学術用語と軽いネットミームを同じ問題群に並べてよい。

## 2. クリップを題材にするときの考え方

このプロジェクトの題材源は自分でクリップした web ページである。以下を意識する。

- **クリップの主題そのものが答えとは限らない。** 記事の中で「へえ」と思わせる脇の事実の方が
  問題になりやすい（制度の名前、語源、初出の年、意外な人物の関与など）。
- クリップした時点で自分が興味を持ったという事実自体が題材選定のシグナルである。
  ただし「自分だけが面白いと思う細部」に寄りすぎると出題として成立しないので、
  答えが一般に知られている語かどうかは別途チェックする。
- 1つのクリップから最大 2 問まで。同じ記事から似た切り口の問題を量産しない。
- 技術記事・ニュース記事は陳腐化が早い。「現在の〜」を答えにする問題は避け、
  年で固定できる事実（発表年・策定年・初出）を使う。

## 3. 避ける題材

- 存命の一般人（公人でない個人）に関する事実。
- 訃報・事件事故・係争中の話題など、扱いに配慮が要るもの。
- 直近数ヶ月で変わり得る肩書き・順位・記録（使う場合は年月を問題文に明記する）。
- クリップ元が個人ブログや掲示板のみで、一次情報にたどり着けないもの。

## 4. ジャンル配分

`config/genre_targets.yaml` に目標があればそれに従う。指定がない場合でも、
クリップの分野が偏っているとそのまま出題が偏るため、`clip_index.py --unused` の結果から
分野の異なるクリップを選ぶこと。
